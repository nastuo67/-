Лекция 6

Цель:

Cформировать понимание основных моделей жизненного цикла программного обеспечения, их особенностей, преимуществ и недостатков, а также умение выбирать подходящую модель для конкретного проекта.

Жизненный цикл ПО - это период времени от момента появления идеи о создании программного продукта до момента его полного вывода из эксплуатации.

Основные этапы жизненного цикла:

  • Анализ требований
  • Проектирование
  • Разработка (кодирование)
  • Тестирование
  • Внедрение
  • Сопровождение

Модель жизненного цикла — это схема, которая описывает, как этапы связаны между собой.

Суть - этапы выполняются строго последовательно. Переход к следующему этапу возможен только после полного завершения предыдущего. Возврат назад не предусмотрен.

Плюсы:

  • Простая и понятная
  • Чёткое планирование сроков и бюджета
  • Хорошо документирована
  • Подходит для проектов с чётко определёнными требованиями

Минусы:

  • Нельзя вернуться на предыдущий этап
  • Тестирование — в самом конце, ошибки дорого исправлять
  • Заказчик видит результат только в конце
  • Плохо работает при изменении требований

Когда применять:

  • Проекты с фиксированными требованиями
  • Государственные и оборонные заказы
  • Небольшие проекты с понятной задачей

Инкрементая модель

Суть - проект разбивается на инкременты (части). Каждый инкремент — это полный цикл разработки (от требований до внедрения), но для части функциональности. Продукт растёт постепенно.

Плюсы:

  • Заказчик видит результат после каждого инкремента
  • Можно изменять требования между инкрементами
  • Раннее тестирование и отладка
  • Можно начать использовать продукт раньше

Минусы:

  • Требует хорошего планирования архитектуры
  • нужно чётко определить границы каждого инкремента
  • Возможны проблемы интеграции между частями

Когда применять:

  • Крупные проекты, которые можно разбить на части
  • Когда заказчик хочет видеть прогресс
  • Проекты с эволюционирующими требованиями

Спиральная модель (Spiral) Год появления: 1986, Барри Боэм.

Суть - это эволюция, где каждый виток спрали - это полный цикл разработки с акцентом на анализ рисков. Каждый виток проходит 4 фазы:

  1. Определение целей — что делаем на этом витке?
  2. Анализ рисков — что может пойти не так?
  3. Разработка и тестирование — создание прототипа.
  4. Планирование следующего витка — что делаем дальше?
